# ADR 0001 — Общая архитектура

## Статус
Принято.

## Контекст
PSA для 200+ пользователей: проекты, трудозатраты, калькулятор лицензий,
финансы, ресурсы, дашборды. Нужна поддерживаемая, тестируемая, готовая к
переезду в Kubernetes система.

## Решение
- **Монорепо**: `backend/` (FastAPI) + `frontend/` (React).
- **Backend — слоистая архитектура**: `router → service → repository`.
  Роутеры тонкие (валидация ввода, проверка прав), бизнес-логика только в
  сервисах, доступ к данным — в репозиториях. Это изолирует ядро ценности
  (калькулятор, финансы) и делает его покрываемым unit-тестами без HTTP/БД.
- **Async везде**: FastAPI + SQLAlchemy async + asyncpg. Блокирующие операции
  (генерация XLSX, обмены с 1С) выносятся в Celery.
- **Деньги — только `Decimal` / `NUMERIC(15,2)`**, часы — `NUMERIC(5,2)`.
  Никаких float в финансовых расчётах.
- **Ролевые Response-схемы**: финансовые поля (cost_rate, маржа) не попадают в
  общие схемы; для engineer/presale отдаётся «безопасная» схема. Фильтрация на
  уровне Pydantic, не на фронте.
- **12-factor**: конфигурация только через env, stateless backend, состояние в
  Postgres/Redis.

## Последствия
- Чёткое разделение слоёв требует чуть больше «церемоний», но окупается
  тестируемостью ядра.
- Ролевые схемы дублируют часть полей — осознанный компромисс ради безопасности
  финансовых данных.
