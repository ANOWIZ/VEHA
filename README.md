# Веха — управление проектами и работой команды

Учебный прототип PSA-системы: проекты, задачи, трудозатраты, загрузка сотрудников, расчёт стоимости работ и лицензий, план-факт бюджета и портал заказчика.

Это обезличенная демонстрационная версия. Все организации, пользователи, реквизиты, цены и финансовые показатели в наборе данных вымышлены. Реальные базы, вложения, настройки серверов и история исходного репозитория не включены.

## Что можно посмотреть в коде

- Ролевой доступ к проектам и финансовым данным.
- Согласование трудозатрат и расчёт себестоимости.
- Калькулятор предложений, скидок и маржи на `Decimal`.
- Учёт рисков, загрузки команды и обязательств заказчика.
- Экспорт отчётов, журнал действий и фоновые задачи.

Основной вариант: React + TypeScript, FastAPI, PostgreSQL, Redis, Celery, Keycloak. В `backend-dotnet/` сохранён альтернативный backend на ASP.NET Core и EF Core с тестами. Названия библиотек, протоколов и интеграционных интерфейсов относятся к стеку, а не к клиентам проекта.

## Локальное демо

Нужен Docker Compose. Используйте отдельный проект и новую базу, не подключайте рабочие данные.

```powershell
Copy-Item .env.example .env
docker compose -p veha-demo up -d --build
docker compose -p veha-demo exec backend uv run python -m app.seed
```

Интерфейс: http://localhost:5173. API: http://localhost:8000/docs. На странице входа выберите тестовую роль. Seed создаёт четыре демо-клиента, три демо-вендора, двенадцать пользователей и шесть проектов.

Все порты основного Compose доступны только на localhost. Публичные пароли `psa`, `admin`, `demo` и dev-JWT предназначены исключительно для локального примера. Не размещайте эту конфигурацию в интернете.

## Проверки

```powershell
cd frontend
npm ci
npm run typecheck
npm run lint
npm run build
```

Python 3.12 и uv:

```powershell
cd backend
uv sync --extra dev
uv run pytest tests/unit
```

Для интеграционных тестов нужна отдельная PostgreSQL-база с применёнными Alembic-миграциями. Тесты могут изменять данные; не запускайте их против рабочей базы.

```powershell
dotnet test backend-dotnet/Veha.sln
```

## Ограничения

Это прототип и пример кода, не подтверждённое промышленное внедрение. Локальные интеграции не подключены к внешним учётным системам. Перенос данных между Python- и .NET-бэкендами здесь не выполняется. Перед любым боевым использованием нужны отдельная проверка безопасности, настройка OIDC, секретов и инфраструктуры.

Состав обезличивания и его границы описаны в [PUBLICATION_AUDIT.md](PUBLICATION_AUDIT.md).
